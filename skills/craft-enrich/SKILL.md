# craft-enrich — обогащение крафтового каталога

## Зачем это нужно

Сырые источники дают разрозненное и неполное: магазин знает цену, но не стиль;
канал пивоварни знает стиль и ABV, но не цену; имена одного сорта различаются
(«Крылья отваги» vs «Kryly Advagi»). Задача скилла — собрать из этого **одну
адекватную запись**: характеристики из первоисточника, цены из магазинов, всё
связано, размечено и дедуплицировано. Это слой «петли» Beer Log
(`vault/product/mvp.md`): supply (что варят) ↔ demand (что берут/почём).

Человек/агент собирает «сырьё», а этот скилл наполняет каталог проверенными
данными. Не выдумывай того, чего нет в источнике — лучше оставить поле пустым,
чем угадать.

## Приоритет источников (Telegram-first)

Бери данные в этом порядке, не усложняя без нужды:

1. **Telegram — основной источник.** У пивоварен официальный канал
   (`t.me/s/<handle>`) в каждом релизе даёт имя, стиль, ABV/Plato/IBU и описание —
   это лучший источник характеристик. У магазинов TG-каналы дают наличие/цены/новинки.
2. **Сайты/витрины магазинов** — цены, остатки, объём, иногда ABV/цвет.
3. **Официальный сайт пивоварни** — часто лендинг без каталога; берём контакты/ссылки.
4. **VK — только крайний вариант**, когда сорта/данных нет ни в TG, ни в магазинах.
   VK дублирует TG, а парсить дороже — не трогаем, пока есть TG.
5. **Untappd** — заблокирован в РФ, данные проприетарны: не источник.

Почему так: Telegram отдаёт публичное веб-превью без API-ключа, формат релизов
структурный, аудитория и пивоварен, и магазинов там же. См. `references/source-formats.md`.

## Конвейер обогащения

Делай по шагам; пропускай нерелевантные.

1. **Определи тип источника.** Релиз из канала пивоварни (есть строка
   `Алк % / Plato / IBU`) → характеристики. Листинг магазина (есть цена ₽) → спрос.
2. **Разбери релиз пивоварни.** Формат и парсер — в `references/source-formats.md`.
   В проекте уже есть `parseBreweryReleases` (`packages/parsers`): имя, `styleRaw`,
   `abv`, `plato`, `ibu`, `description`.
3. **Нормализуй стиль.** Прогони `styleRaw` через `categorizeStyle`
   (`@beer-log/catalog-core`) → `category` (ipa/sour-wild/stout-porter/…). В поле
   `style.name` оставляй исходный стиль из источника (напр. «IPA - New England /
   Hazy»), в `category` — нашу таксономию. Не подходит — `unknown`, не выдумывай.
4. **Собери теги.** Кураторски, не свалкой: стиль (NEIPA, гозе, сауэр), ключевые
   вкусо-аромат ноты из описания (мандарин, малина, кофе), формат (сессионное,
   крепкое по ABV), плюс бренд и город. 4–8 тегов. Теги нужны для discovery/мета —
   они должны помогать искать, а не повторять название.
5. **Собери ссылки.** Официальные (TG-пост, сайт, VK, Untappd) + URL магазинов, где
   найден сорт. Ссылка на конкретный TG-пост = провенанс характеристик.
6. **Привяжи цены.** Из листингов магазинов: `{shop, price, volumeMl, остаток?}`.
   Если сорт в нескольких магазинах — массив; посчитай min/max (разброс = сигнал).
7. **Дедуп между источниками.** Используй `isSameBeer` (`@beer-log/catalog-core`,
   fuzzy: транслит-slug + Левенштейн, порог 0.85). Точные/нормализованные
   совпадения сливай автоматически. Искажённый транслит fuzzy не ловит
   («Крылья отваги» ↔ «Kryly Advagi» = 0.83) → добавляй **ручной алиас**. Спорное
   (0.7–0.85) — помечай на ручную проверку, не сливай молча.
8. **Поставь статус.** `validated` — если характеристики из официального источника
   (канал/сайт пивоварни). `auto` — если только из магазинов/реестра (нужна
   проверка). Статус честно отражает доверие к данным.
9. **Запиши.** В каталог через `upsertBeer`/`recordListing` (`@beer-log/store`,
   дедуп по slug встроен) и/или верни обогащённый JSON (формат ниже).

Готовый сквозной шаблон конвейера — `scripts/enrich.ts` (импортирует
`@beer-log/parsers|catalog-core|store`). Бери его за основу, не переписывай с нуля.

## Формат обогащённой записи

```json
{
  "name": "Hazy shade of summer",
  "brewery": "Rewort Brewery",
  "city": "Сергиев Посад",
  "style": "IPA - New England / Hazy",
  "category": "ipa",
  "abv": 6.5, "plato": 16.5, "ibu": 25,
  "description": "Сочно-мутный NE IPA с мандариновым соком…",
  "tags": ["NEIPA", "хейзи", "цитрус", "мандарин", "Rewort"],
  "links": ["https://t.me/RewortBrewery/761", "https://rewort.ru", "https://craftbeer78.ru"],
  "prices": [{ "shop": "craftbeer78.ru", "price": 269, "volumeMl": 500 }],
  "priceMin": 269, "priceMax": 269,
  "aliases": ["Kryly Advagi"],
  "status": "validated",
  "provenance": { "source": "telegram:@RewortBrewery", "post": "https://t.me/RewortBrewery/761" }
}
```

## Принципы качества

- **Верность источнику.** Описание — пересказ/сокращение реального текста, не
  выдумка. Стиль/ABV/IBU — только из источника; нет → пусто/`unknown`.
- **Дедуп честный.** Авто-слияние только при уверенном совпадении; остальное — алиас
  или флаг на ревью. Лучше дубликат на проверке, чем неверное слияние.
- **Провенанс всегда.** Каждая характеристика тянет ссылку на источник — чтобы
  переразобрать и чтобы пивоварня/байер видели, откуда данные.
- **Не усложняй источники.** Хватает TG — не лезь в VK. Хватает 2 магазинов — не
  гонись за десятым.

## Примеры

**Пример 1 — релиз из канала пивоварни.**
Вход (TG-пост):
```
Hazy shade of summer
IPA - New England / Hazy
Алк 6.5% / Plato 16.5% / IBU 25
Сочно-мутный представитель восточного побережья… добавили мандариновый сок.
#rewort #сергиевпосад
```
Выход: запись со `style="IPA - New England / Hazy"`, `category=ipa`, `abv=6.5`,
`plato=16.5`, `ibu=25`, теги `[NEIPA, хейзи, цитрус, мандарин, Rewort]`, ссылка на
пост, `status=validated`.

**Пример 2 — свести один сорт из двух магазинов.**
Вход: «Крылья отваги» — craftbeer78 269 ₽; «Kryly Advagi» — winestyle 259 ₽.
`isSameBeer` даёт 0.83 (< 0.85) → не авто-слияние. Действие: добавить алиас
«Kryly Advagi» к «Крылья отваги», объединить в одну запись, `prices` = оба магазина,
`priceMin=259/priceMax=269`. Пометить, что слияние через алиас (ручное).

## Где код проекта

- `packages/parsers` — `parseBreweryReleases` (релизы TG), `telegramWebParser`,
  `parseRcbExport` (реестр).
- `packages/catalog-core` — `categorizeStyle`, `isSameBeer`/`normalizeName`/`nameSimilarity`, `slugify`.
- `packages/store` — `upsertBrewery`/`upsertBeer`/`recordListing` (дедуп по slug, история цен).
- Эталон применения — `scripts/enrich-rewort.ts` в репозитории.
