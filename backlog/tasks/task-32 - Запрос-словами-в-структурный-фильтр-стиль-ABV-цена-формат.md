## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Подзадача B2. Естественный запрос «кислое до 500», «что покрепче но не очень», «лёгкое пшеничное на
вынос» → один дешёвый LLM-вызов парсит в структурный фильтр {style, abvRange, priceMax, format} → SQL
по пулу точки. LLM только на парс запроса (редко, дёшево), не в матче и не на каждый чих. Без запроса —
обычные фильтры из UI.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Парсер запроса → `QueryFilter {style?, abvMin?, abvMax?, priceMax?, format?, tasteTags?}`
      (`scripts/lib/query-filter.ts` `parseQuery`). В боте парсит САМ агент (он и есть дешёвый LLM, на
      подписке) и передаёт структурные флаги; `--q` включает встроенный RU-лексикон-фолбэк (стили-синонимы,
      крепость, «до N»=цена vs «до N%»=ABV, «на вынос»/«на кране»=формат). 6 юнит-тестов на разбор зелёные.

      пустом результате: ослабляет условия в порядке format→price→abv→**style (ядро, последним)**,
      возвращает `relaxed[]` (что ослаблено) для честного ответа. 3 юнит-теста на SQL+деградацию зелёные.
- [x] #3 Прогон на Beer Mug (`beerlog filter --demo beermug-nn/gagarina-118`): «кислое до 500»,
      «крепкий стаут», «лёгкое на вынос», «что покрепче но не очень», «лёгкое пшеничное на вынос» —
      непустой осмысленный ответ 5/5 (где точного нет — честное ослабление, видно в `relaxed`).

## Implementation Notes
<!-- SECTION:NOTES:BEGIN -->
beers уже имеет style_name/style_category/abv. format в листинге. tasteTags пока опц. (descriptors из tastings/каталога). Кэшировать частые запросы. Не смешивать с fuzzy-именем (TASK-30) — это другой вход.

**Реализовано (2026-06-08).** `scripts/lib/query-filter.ts` (`parseQuery` + `runFilter`),
CLI `scripts/bot-filter.ts` (`beerlog filter --seller <s> --q "…"` | структурные флаги | `--json` |
`--demo`), регистрация в `beerlog.ts`, интент **#2b** в `beer-concierge/SKILL.md` (агент-парсер,
честная подача `relaxed`), 9 тестов в `tests/bot.test.ts` (20/20 зелёные), typecheck чистый.
- **«LLM только на парс»** реализовано в духе архитектуры «бот = Claude»: разбор делает сам агент
  (на подписке, без API-вызова), скрипт детерминирован. Лексикон в `query-filter.ts` — фолбэк и
  опора тестируемости #3; он же даёт деградацию без сети.
- **Деградация** (#2): порядок ослабления format→price→abv→style — стиль как ядро намерения роняется
  последним; `relaxed[]` пробрасывается в ответ, бот честно говорит «точно такого нет, вот близкое».
- **tasteTags** принимается схемой, но в SQL не маппится (нет надёжного источника дескрипторов на
  каталожных beers) — зарезервировано, не выдаём за работающее.
- **Кэш частых запросов** из исходного замысла НЕ делал: один SQL по пулу точки (≤50 листингов) дешёв,
  кэш преждевременен. Вернуться, если фильтр пойдёт по объединённому мульти-seller пулу.
<!-- SECTION:NOTES:END -->
