# AGENTS.md — схема проекта Beer Log

Этот файл — конфигурация для ИИ-агентов (Claude и др.), работающих над проектом.
Он описывает, как устроена документация, код и парсеры, и какие рабочие процессы
соблюдать. Co-evolve этот файл по мере того, как становится понятно, что работает.

## Что за проект

Закрытый B2B-каталог/маркетплейс крафтового пива в РФ. Полный контекст и
обоснование — `vault/strategy/gtm.md` и `vault/raw/beer-b2b-marketplace-gtm.md`.
Однострочно: не «русский Untappd для потребителя» (нелегально), а закрытый B2B —
discovery-витрина для байеров → аналитика спроса как платный продукт для
пивоварен → единое окно заказа.

## Три слоя (паттерн «LLM Wiki» Карпатого)

1. **Raw-источники** — `vault/raw/`. Иммутабельны. Агент читает, но не правит.
2. **Вики** — `vault/` (кроме raw). Связанные md-страницы: стратегия, продукт,
   ресёрч, рост. Агент владеет этим слоем целиком: создаёт страницы, обновляет
   при новых источниках, поддерживает перекрёстные ссылки `[[wikilink]]`.
3. **Схема** — этот файл. Конвенции и рабочие процессы.

Навигация: `vault/index.md` (каталог страниц), `vault/log.md` (хронология).

## Рабочие процессы

### Ingest (новый источник/инсайт)
Прочитать → обсудить ключевое с Кириллом → обновить релевантные страницы вики →
обновить `vault/index.md` → дописать строку в `vault/log.md` с префиксом
`## [YYYY-MM-DD] ingest | <название>`.

### Query (вопрос к вики)
Сначала прочитать `vault/index.md`, найти релевантные страницы, синтезировать
ответ со ссылками. Ценный ответ — зафайлить обратно в вики новой страницей.

### Lint (здоровье вики)
Искать: противоречия между страницами, устаревшие утверждения, страницы-сироты
без входящих ссылок, важные концепты без своей страницы, пробелы в данных.

## Код

- Стек: **Bun + TypeScript**. Монорепо, bun workspaces (`packages/*`).
- `@beer-log/catalog-core` — доменные модели + таксономия стилей. Без внешних
  зависимостей.
- `@beer-log/parsers` — фреймворк парсеров + Telegram-прототип.
- `@beer-log/web` — витрина-справочник: **SvelteKit + Svelte 5 (runes) + Vite**,
  статичная сборка (`adapter-static`). Данные — JSON-снапшот, генерится
  `scripts/export-catalog.ts` из `catalog.sqlite` (никакой БД в рантайме). UX-спека:
  `vault/product/reference-site-ux.md`. Команды: `bun run web` / `bun run web:build`.
  Перегенерируй снапшот после ingest/seed. Веб-пакет исключён из корневого
  `tsc` (у него свой `svelte-check`).
- Импорты внутренних пакетов: `@beer-log/catalog-core` (см. paths в tsconfig).
- Перед коммитом: `bun run typecheck`.

## Парсеры и самовосстановление

Каждый парсер реализует интерфейс `Parser` (`packages/parsers/src/types.ts`) с
методом `healthCheck`. Парсеры должны уметь «чинить себя»: когда healthCheck
падает (источник изменил разметку), запускается агент-фиксер, который по
`description` парсера и сырому снапшоту правит экстрактор. Детали —
`vault/product/parser-architecture.md`.
