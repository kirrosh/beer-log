# Модель данных каталога

Зеркалит `packages/catalog-core/src/models.ts`. Здесь — смысл и решения.

## Сущности

- **Brewery** — пивоварня. Поле `segment` (`craft`/`mainstream`/`unknown`)
  определяет [[positioning|фокус монетизации]]: краф монетизируем, мейнстрим —
  бесплатные «обои».
- **Beer** — сорт. `status` (`auto`/`validated`/`rejected`) — почти весь ingest
  автоматический, человек только валидирует (см. [[autonomy]]).
- **BeerStyle** — нормализованный стиль + `category`. Категоризация —
  `styles.ts` (регэксп-правила, рус+англ). Поле `raw` хранит исходную метку.
- **PriceListing** — ценовое предложение из источника (цена, объём, формат
  bottle/can/keg/draft). Сырьё для аналитики и для байера.
- **Source / SourceRef** — провенанс. Каждая запись хранит, откуда пришла, с
  `excerpt` исходного текста — чтобы можно было переразобрать при изменении
  логики парсинга.

## Решения

**Провенанс везде.** Любая сущность тянет за собой источник и фрагмент текста.
Это позволяет (а) переразбирать старые данные новым экстрактором, (б) показывать
байеру откуда инфа, (в) чинить парсеры на реальных примерах.

**Дедуп по slug + алиасам.** `slugify` транслитерирует кириллицу. Одинаковые
пивоварни/сорта из разных каналов сливаются. Алиасы накапливают варианты
написания. Реализация дедупа — `task-3`.

**Умная категоризация стилей.** Сейчас — правила. Дальше можно добавить
LLM-классификацию для неоднозначных случаев (категория `unknown`).
