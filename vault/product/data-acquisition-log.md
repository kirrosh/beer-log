# Data acquisition log — как и откуда собираем

Живая «база знаний» о сборе данных: как мы движемся, какие источники, что уже
покрыто, чего ещё нет, и здоровье источников. Дополняет [[log]] (хронология) и
бэклог (задачи): здесь — **состояние данных и метод**, а не события и не задачи.
Обновляется после каждого прохода сбора.

## Алгоритм одного прохода сбора (петля)

1. **Discover** — кто существует и **активен**: агентная разведка (компиляция +
   верификация по живым каналам/наличию в магазинах) → пивоварни + офиц. ссылки.
   Реестр russiancraftbeer как несущий источник отпал (export сломан, см. ниже);
   магазины — точечно за ценами. «Активна» = живой канал ИЛИ есть в магазинах.
   ([[sourcing-strategy]], task-12)
2. **Official** — что варят: офиц. каналы пивоварен (VK/Telegram), наведённые на
   хэндлы из шага 1. (task-13)
3. **Demand** — что берут / почём: витрины магазинов и заведения → цены, остатки,
   скидки. (task-10, task-1)
4. **Merge** — дедуп/идентичность между источниками (fuzzy, транслит). (task-14)
5. **Report/meta** — собрать витрину/отчёт ([[reference-site]]).
6. **Update** — дописать сюда (покрытие+пробелы) и в [[log]]; завести задачи на дыры.

- Пивоварни: **68 в `data/catalog.sqlite`** (38 городов). Слои: сид ~20 из

  посты/чек-ины 2025-26) + офиц. ссылки; хэндлы проверены (`t.me/s/`), не выдуманы.
  Колонка `breweries.links`. Батч: `data/discovery/batch-2026-05-29.json`, сидер
  `scripts/seed-breweries.ts` (переиспользуемый). Топ-обогащение: `seed-top-breweries.ts`.
- **Сорта из офиц. каналов (task-13): ~280 сортов** (глубокий проход 2026-05-29 по
  25 каналам, 2 страницы превью каждый). Статус validated, провенанс на канал, стили
  по таксономии. Извлечено **агентно** (формат релиза у каждой пивоварни свой — regex
  `parseBreweryReleases` не генерализуется). Источник-данные: `data/ingest/sorts-2026-05-29/g*.json`,
  скрипт `scripts/ingest-sorts.ts`. **Хинты для инкрементальных проходов:
  `data/ingest-hints.json`** (по каждой пивоварне: канал, метод, дата, newest/oldest
  post id, сколько сортов, статус). Дрейф (0 текст. сообщений через `t.me/s/`,
  медиа-посты): `@jawsbrewery`, `@hopheadbrewery`, `@petzold_brewpub` — нужен caption/VK.
- Rewort: 50 листингов в 2 магазинах (СПб+Мск), ABV по части сортов, остатки по
  части — `data/rewort-catalog.sqlite`, отчёт `data/rewort-loop-report.md`.
- **Rewort обогащённый: 7 сортов из TG-первоисточника** (стиль, ABV/Plato/IBU,
  описание, теги, ссылки) + цены из магазинов, статус validated —
  `data/rewort-enriched.sqlite` / `.json`, отчёт `data/rewort-enriched-report.md`.
  Это и есть агентное обогащение: «сырьё» → адекватные записи (позже автоматизирует
  скилл). Дедуп: fuzzy (`isSameBeer` в catalog-core) + ручные алиасы.

  server-rendered, коллекции по пивоварням). 33 листинга склеены с каноном (`isSameBeer`,
  обе половины заголовка рус/eng), 682 снапшота цен (`price_snapshots` → детект скидок при
  повторе во времени), наличие захвачено (напр. Jaws 67/70 нет в наличии — сигнал спроса).
  Парсер `parseInsalesProducts`/`shopTitleToBeerName`, скрипт `scripts/ingest-shop.ts`
  (карта slug→коллекция, расширять). Несвязанные листинги (beerId=null) хранят ассортимент
  без засорения канона; промоушн в канон — отдельный курируемый/агентный проход.
  Экспорт витрины несёт сигнал спроса на сорт (`beer.demand`: listings/sellers/discounted).
- Подтверждённая петля: supply (сорта) ↔ demand (цены/наличие). Замкнулась end-to-end:
