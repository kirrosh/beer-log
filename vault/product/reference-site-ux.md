# Reference-site — UX-спека витрины (task-11)

Конкретный UX «тонкой витрины» под направление [[reference-site|«Dotabuff
российского крафта»]]. Это слой подачи поверх каталога: рендерит то, что есть в
`data/catalog.sqlite`, мета — из наблюдаемых сигналов (стили/города/новинки), без
субъективных оценок (юр-рамка ст. 21 — рыночные данные, не потребительский рейтинг).

## Принципы

- **Information-first, tool-like.** Плотно, быстро, как терминал/Dotabuff, а не
  глянцевый лендинг. Числа — моноширинным, табличные цифры.
- **Мета = визуализация наблюдаемого.** Распределение стилей, охват городов,
  новинки — то, что у нас реально есть. Не выдумываем рейтинги.
- **Цвет несёт смысл.** Каждой категории стиля — свой цвет (chip), это и навигация,
  и мета-картина каталога одним взглядом.
- **Тонко и статично.** Клиентская фильтрация по JSON-снапшоту, статичная сборка
  (никакой БД в рантайме) — соответствует «тонкой витрине» из бэклога.

## Стек

SvelteKit + Svelte 5 (runes) + Vite, запуск Bun, `adapter-static` (полностью
статичная сборка). Данные: `scripts/export-catalog.ts` читает `catalog.sqlite` →
`packages/web/src/lib/data/catalog.json`. Витрина импортирует JSON, фильтрует на
клиенте, детальные страницы пререндерятся обходом ссылок.

## Эстетика

- Тёмная, тёплая (хмель/медь). Фон ~`#0e0f12`, поверхности с hairline-границами.
- Шрифты: дисплей **Saira Condensed** (индустриальный, кириллица), тело **Golos
  Text** (русско-нативный), данные **JetBrains Mono**.
- Акцент — янтарь `#e9a23b`. Категории стилей — своя палитра (ipa=янтарь,
  sour-wild=маджента, stout-porter=обжарка, lager=золото, wheat=пшеница,
  pale-ale=хмель-грин, belgian=оранж, specialty=бирюза).
- Движение сдержанное: staggered-проявление мета-чисел и строк на загрузке, hover
  со сменой левой границы строки на цвет категории.

## Экраны

### `/` — каталог + мета
1. **Шапка:** вордмарк `BEER LOG`, таглайн «мета российского крафта», глобальный поиск.
2. **Мета-полоса:** крупные mono-числа (Пивоварни · Сорта · Города · Стили) +
   горизонтальный stacked-бар распределения по категориям стилей (ширина ∝ кол-ву,
   цвет = категория) с легендой и счётчиками.
3. **Тулбар:** поиск, переключатель вида `Сорта | Пивоварни`, сортировка.
4. **Фильтры:** chip-и категорий (мультивыбор, цветные), город, мин. ABV, статус
   (validated/auto), «есть офиц. TG».
5. **Список (плотный):**
   - *Сорта:* Название · Пивоварня (город) · chip категории · стиль · ABV · IBU · статус. Строка → `/beer/<slug>`.
   - *Пивоварни:* Название · город · сегмент · кол-во сортов · иконки ссылок (сайт/TG/VK). Строка → `/brewery/<slug>`.

### `/beer/<slug>` — карточка сорта
Имя, пивоварня (ссылка) + город, chip категории, стиль; mono-ячейки ABV/IBU/Plato
(нет → «—»); описание (из провенанса); ссылки-источники; алиасы; «другие сорта
пивоварни».

### `/brewery/<slug>` — карточка пивоварни
Имя + алиасы, город/сегмент, кнопки офиц. ссылок (сайт/TG/VK/Untappd); мини-мета
(распределение её сортов по стилям); сетка её сортов.

## Состояние данных и честность

- Описание сорта — из `beer_sources.excerpt` (провенанс). `tags`/`plato` пока **не
  персистятся** в каноне (были только в скриптах обогащения) — в витрине v1 их нет;
  если понадобятся для фильтров/меты — добавить колонки в `beers` (см. [[data-model]]).
- Пустые поля показываем как «—», не выдумываем.
- Цен пока нет (demand-слой впереди, task-10/14) — блок «наличие/цены» появится
  позже как мета спроса.

## Что дальше (после v1)

- Мета спроса: цены/наличие/скидки по городам (task-10/14) → таблицы «где купить».
- «Новинки» по дате релиза (нужна дата поста в провенансе).
- Теги/Plato в каноне → фасетный поиск по вкусо-аромату.
