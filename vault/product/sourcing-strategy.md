# Стратегия источников данных (слоёная)

Решение (Кирилл, 2026-05-29): не полагаться ни на один источник. Каждый слой
отвечает за своё, данные сливаются с провенансом и дедупом ([[data-model]]) —
чтобы смерть любого источника (как RateBeer/taplist) не убивала каталог.
Приоритет Фазы 0 — **полнота справочника** (ширина), потом глубина/актуальность.

## Почему не «парсить каждую пивоварню» как единственный метод

Пивоварен 300–500, у каждой свой сайт (Tilda/VK/Telegram/Instagram/кастом) — это
сотни bespoke-парсеров, которые постоянно «плывут». Тупик по поддержке. И прежде
чем парсить пивоварню, надо знать, что она существует — нужен слой обнаружения.

## Почему не полагаться на russiancraftbeer

Это стареющий реестр (страницы правились в 2017). Как источник правды — нет. Но он
отлично решает обнаружение: на странице пивоварни лежат её **официальные ссылки**
(сайт/VK/Facebook) + город + список сортов. То есть реестр — это карта к
официальным источникам, а не сам источник.

## Три слоя

**Слой 1 — Discovery (кто существует).** Реестры (russiancraftbeer полный обход) +
брендовые списки магазинов (craftopt, craftbeer78) + profibeer. Выход: перечень
пивоварен + их офиц. ссылки. Доверяем только перечню, не данным. Бэклог: `task-12`.

**Слой 2 — Authoritative (что варят, новинки).** Официальные каналы пивоварен. На
практике это почти всегда VK/Telegram, а не уникальный сайт → 1–2 универсальных
парсера (TG есть, VK добавить), наведённые на хэндлы из Слоя 1. Bespoke-парсер
сайта — только для крупных пивоварен со структурным каталогом. Бэклог: `task-13`,
`task-2`.

**Слой 3 — Demand signal (что берут / что не продаётся, цены).** Магазины и
заведения — по определению вторичные источники, но именно тут ценность
[[mvp|петли]]. Цены, скидки (= медленные позиции), наличие, прайсовые TG-каналы.
Бэклог: `task-10`, `task-9`, `task-1`.

## Сквозное

- **Многоисточниковость + провенанс + дедуп** (встроено в `store`) = нет единой
  точки отказа. Межисточниковая идентичность (fuzzy, транслит) — `task-14`.
- **Самовосстановление парсеров** (`task-5`): больше источников → больше дрейфа →
  важнее агент-фиксер по `healthCheck` ([[parser-architecture]]).

## Приоритет (полнота справочника первой)

Критический путь Фазы 0: `task-12` (discovery, ширина) → `task-13`/`task-2`
(наполнение из офиц. каналов) → `task-14` (склейка) → `task-11` (открытый
справочник). Слой спроса (`task-1/9/10`) — параллельно, но вторичен по приоритету.
