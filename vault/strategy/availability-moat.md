# Граф доступности — наш ров

> Связано: [[drift-to-value]], [[positioning]], [[need-and-demand]], [[untappd]],
> [[monetization]], `vault/product/data-model.md`.

Решением [[drift-to-value|task-19]] (2026-06-01) **граф доступности** назван
первичным рвом проекта. Эта страница — что это, почему ров, как устроено сейчас и
куда растёт.

## Что это

Граф доступности — это связи **сорт ↔ точка продажи** (магазин или бар), снятые из
наблюдаемых источников. Ребро = «сорт X встречается у продавца Y» с атрибутами:
формат (`bottle`/`can`/`keg`/`draft`), цена (если есть), флаг скидки, дата снапшота,
провенанс (откуда и фрагмент текста). Технически рёбра — это `PriceListing`
(`packages/catalog-core/src/models.ts`), агрегаты считает `scripts/export-catalog.ts`.

Из графа выводятся ключевые метрики «меты»:
- **reach сорта** — у скольких разных точек он встречается (число уникальных
  продавцов; опт входит в reach, но не в «цену от»).
- **reach пивоварни** — объединение точек по всем её сортам (`{reach, listings,
  listedBeers}`).
- **«цена от»** — минимум по РОЗНИЧНЫМ листингам (опт исключён, мешать нельзя).
- **скидка** — снижение цены по позиции во времени = пассивный сигнал «что плохо
  продаётся» (см. `data-model.md`, [[approach|build-to-learn]]).

Витринное проявление — страница `/top` (топ по ширине дистрибуции) и будущий блок
«Где найти» на карточках (`task-20`).

## Почему именно это — ров

1. **Это наши собственные данные, которых нет ни у кого.** [[untappd|Untappd]]
   (ушёл из РФ) знал рейтинги, но **не знал, где купить/выпить**. РусБир — это
   Москва + он сам продавец (конфликт интересов). russiancraftbeer — реестр, поплыл.
   Кросс-поставщиковую, всерос., нейтральную карту доступности независимого крафта
   не даёт никто ([[need-and-demand]]).
2. **Граф нельзя «сбутстрапить» из чужого API** — в отличие от рейтингов
   ([[reference-site|RateBeer/Untappd проприетарны]]). Его собирают ногами по
   источникам; это работа, которая и создаёт защиту.
3. **Он прямо обслуживает выбранную аудиторию** — конечного юзера в режиме «что
   попробовать / где это взять».
4. **Он же субстрат для монетизации потом** — из тех же рёбер во времени растёт
   [[monetization|аналитика спроса для пивоварен]] (что смотрят/где есть/что
   уценивают), не требуя переделки.

## Планка надёжности — намеренно низкая

Карта доступности — НЕ живой остаток. Достаточно: «этот сорт обычно водится вот
тут» + **дата снапшота**. Это снимает «стену источников» ([[drift-to-value]]): можно
тянуть ненадёжные freeform-источники (TG-тап-листы баров), потому что best-effort с
датой — уже ценность. Источник ребра = что угодно публичное: e-commerce каталог,
сайт магазина, **TG-канал бара** (паттерн «бар → тап-лист»,
`scripts/ingest-vashchehov.ts`, memory `draft-bar-tg-taplist`).

## Открыто vs под замком

- **Открыто** (нейтральная рыночная информация): сам граф — где сорт встречается,
  «цена от», разлив/бутылка, дата, reach, тренды. Рамка ст.21 — см. [[risks]].
- **Под замком** (дверь монетизации): гранулярная аналитика спроса-как-продукт для
  пивоварен (срезы, динамика, «смотрят и не заказывают»). См. [[monetization]].

Граница «открыто/закрыто» проходит между **доступностью** и **аналитикой-как-продукт**,
а не между «агрегат/гранул» (см. [[mvp-research-mode]]).

## Что есть и чего не хватает

- **Есть:** рёбра из 7 продавцов (магазины + первый бар), reach-метрики, `/top`,
  детект скидок, дедуп сорта/пивоварни между источниками (catalog-matcher).
- **Тонко:** потолок reach ≈ 5 (просканировано мало точек) — граф растёт с каждым
  новым продавцом. Нет геопривязки точек (город есть только у пивоварен).
- **Дальше:** сделать граф видимым (`task-20` «Где найти»); добрать точки —
  магазины (`shop-discovery`) и TG-бары (`task-1`); привязать листинги к городу;
  тюнинг алиасов матчера (известные пивоварни иногда не сходятся).
