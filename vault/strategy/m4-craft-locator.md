# Поиск на точке — Craft Locator (майлстоун M4)

> Бэклог: майлстоун `M4: Поиск на точке`. Эпик-карта сценариев — TASK-29.
> Связано: [[availability-moat]], [[drift-to-value]], [[reference-site-ux]], [[monetization]].

## Зачем этот майлстоун

M2 дал «где найти» на уровне города/бара. Реальный визит (Beer Mug, Гагарина-118, 2026-06-04)
вскрыл следующий слой боли: **кран нашёлся (taplink), но холодильник — сотни банок, найти «ту
самую» нереально** → человек берёт замену наугад. Это микро-уровень того же рва: не «в каком
баре есть сорт», а «есть ли он в ЭТОЙ точке, и что взять прямо сейчас».

M4 превращает каталог в **инструмент в моменте покупки**: стоя у полки — мгновенно «есть ли X /
что взять / замена / что не пробовал», по объединённому пулу точки (кран + холодильник).

## Архитектурный принцип: распознавание+поиск — это конвейер, не одно

Не моно-решение (всё через LLM / всё через вектора), а 4 подзадачи, каждой свой инструмент:
1. **фото → текст** (vision) — фон, дорого, не в моменте;
2. **текст → нормализация** — уже есть (`normalizeName`, транслит);
3. **«найти ту самую» по неточному имени** — лексический fuzzy (`catalog-matcher` + FTS5/spellfix),
   НЕ вектора; горячий путь, мгновенно;
4. **«похожее / запрос словами»** — вектора (`sqlite-vec`) + опц. 1 дешёвый LLM-вызов; **вне MVP**.

**Горячий путь vs фон:** агент НЕ в цикле каждого запроса. Фон (агент/ML) — оцифровка холодильника,
предрасчёт индексов, курирование. Момент — дешёвый read (fuzzy + опц. фильтр), ~мгновенно.
Принцип «лучше грубо, чем никак»: каскад деградации точный→fuzzy→только пивоварня→«похожее».

## Интерфейс (решение 2026-06-04)

**Один web на существующем SvelteKit (`@beer-log/web`) → работает И как Telegram Mini App, И как
PWA вне TG.** Стартуем в TG (аудитория, низкий порог), но не завязываемся намертво — риск
доступности TG снят (тот же экран открывается напрямую). Бот тонкий: лаунчер мини-аппа + приём
фото полки + уведомления. Бот-UI с нуля НЕ строим.

## Треки и MVP

- **A. Данные/распознавание (фон):** фото-хранилище полок (S3) + vision→кандидаты→`ingest-shelf`.
- **B. Поиск/матч (горячий путь):** B1 каскад «найти ту самую» (первый) · B2 запрос словами→фильтр ·
  B4 пул точки + личное (×tastings/highlights) · B3 векторные «похожие» — **позже/опц**.
- **C. Интерфейс:** web-экран точки → Mini App + PWA; бот-лаунчер.
- **D. Свежесть/вклад:** «возраст данных» + кэш по точке; фото от пользователя/владельцев.
- **E. Источник Untappd-меню (Tier-A):** трек E, TASK-37..40 (см. §ревизия).
- **F. Сценарий «до точки» (выбор бара):** venue-маркеры liveness/выбор/свежесть БЕЗ точного
  ассортимента — каскад по тиру (Offering N для Tier-A, лента чек-инов для Tier-B → «живой/
  большой выбор/ротация», карты потом). Спасает непустую карточку Tier-B. TASK-41, сиблинг
  TASK-38 (та же fetch-инфра, страница ленты чек-инов вместо меню).

**MVP «для меня»:** B1 (поиск-каскад) + A (оцифровка холодильника) + B4 (пул+личное) + C (минимальный
экран точки). Эмбеддинги, NL-запрос, владельцы-поставщики, кэш — расширения за MVP.

## Разведка открытых источников точки (2026-06-04, Beer Mug Гагарина-118)

Проверка «брать ассортимент точки из открытого веба» дала три вывода, меняющих приоритеты:

1. **Холодильник (банки) из веба НЕ достаётся.** Фото полок на картах/соцсетях сняты издалека —
   этикетки нечитаемы для vision-матча; текстового баночного раздела нет нигде. → Оцифровка
   холодильника возможна только через макро-фото на месте (юзер/владелец) — это трек C/TASK-34,
   не веб. Веб-фото как источник холодильника закрыт.
2. **Достоверность ≠ геометка.** Веб-платформы стрипают EXIF — GPS у веб-фото физически нет.
   Реальный механизм: провенанс источника (`source_type`) + возраст наблюдения (`observed_at`,
   для веб = дата поста, НЕ ингеста) → tier. Реализовано: `scripts/lib/provenance.ts`,
   `price_listings.source_type`. Привязка к точке — через контекст источника, не пиксели.
3. **Кран быстро ротируется → наличие скоропортящееся.** Два среза крана Beer Mug (taplink ↔
   Яндекс-меню/RocketData) пересеклись лишь на ~21%: Selfmade Bfg↔Buster Sword/Kaiju, Plan B
   Отличный План↔Parhelion. Цены вообще несопоставимы (taplink за 1 л, меню без объёма). →
   Единичный срез наличия малоценен без даты; **freshness (TASK-35) поднимается в важности**,
   кросс-валидация источников осмысленна лишь при сопоставимых дате+объёме+match-rate.

Инструмент `scripts/ingest-yandex-menu.ts` (парс меню карт + кросс-валидация наличия + провенанс
`map-menu`) готов, но НЕ залит: другой временной срез по неизвестной дате обновления + match 16%
(импорт вне каталога) → шум. Применять осознанно, когда есть дата актуальности меню.

## Ревизия: Untappd как источник точки (эмпирика 2026-06-04)

Сходили руками в Untappd (браузер, без VPN). Вывод №1 выше («холодильник из веба недостижим»)
**опровергнут для топовых баров.** Картина расслоённая ([[untappd]]):

- **Tier A — топ-бары ведут полное Untappd-for-Business меню.** Братья Крафт (Москва): 244 пива,
  секция `Bottles & Cans` (`?menu_id=`, срез датирован до часа) = **оцифрованный самим баром
  холодильник** с пивоварней/стилем/ABV/IBU/рейтингом/**форматом (Can/Bottle)**/объёмом/ценой ₽,
  машиночитаемо. Пивоварни листа = ровно наш каталог (матч ~100%). → Для Tier A трек **A — это не
  vision/фото, а дешёвый скрейп `menu_id` со свежим таймстемпом**; vision на месте становится
  **фолбэком для Tier B** (хвост без меню, только поток чек-инов). Тулинг: `scripts/ingest-untappd.ts`.
- **Свежесть отчасти решается источником:** у Tier A `observed_at` = таймстемп меню (часы), у Tier B
  = время чек-ина. Это лучшая дата, чем у веб-фото/карт → усиливает линию провенанс+возраст (TASK-35).
- **Окно закрывается:** потребительская активность убывает (проблемы с доступом), но бизнес-меню
  durable (бар платит, обновляет). Исторический граф RF-венью осмысленно харвестить, пока жив.

Это перетряхивает приоритет внутри трека A: добавить **быструю полосу «Untappd-меню → ingest-shelf»
для Tier-A венью** перед/параллельно vision-пайплайну фото. Memory `untappd-venue-not-demand-source`
скорректирована (верно для хвоста, не для топа).

### Разведзонд (2026-06-04, `scripts/recon-untappd-venues.ts`, 19 венью BFS от Google-сидов)
- **63% венью с бизнес-меню** (12/19) — «почти не ведут» опровергнуто на выборке.
- **4 379 priced-рёбер** (Σ сортов) с 12 точек, со срезом-датой; боттлшопы с полным прайсом —
  Пиво и Пена 1200, TBPBar 694, Пиво на Ушинке 337. По РФ (топ Москвы/СПб/миллионников) → грубо
  десятки тысяч рёбер с ценами+датами.
- **Match к каталогу: флор 24%** — занижен (fuzzy + смесь скоупа). Калибровка: matched матчатся
  верно (Zagovor/Velka Morava/Selfmade/Одна тонна ✓), но **Midnight Project, Plague, Осьминогец,
  Заповедник, Gravity, Godbeerg = 0 в каталоге** → меню вскрывают реальные дыры предложения.
  Из 386 «новых» — смесь импорта/сидра/мида (вне канона) и настоящего RU-крафта (→ discovery).
- Цены кранов **by-pour** (300/150мл) ≠ unit бутылок/банок — не мешать в «цена от».

## Вне скоупа M4

Эмбеддинги/рекомендации (B3) — отдельно, когда наберётся профиль. B2B-поставка фото владельцами —
монетизация ([[monetization]]), не ломая нейтральность. Рейтинг-СЕТЬ (свои чек-ины Untappd-стиль) —
по-прежнему НЕ строим (M2). **Импорт оценок из Untappd** в личный слой ([[untappd]] §апстрим) —
концептуально верный ход, но **далёкое будущее** (решение Кирилла 2026-06-04), не текущий приоритет.
