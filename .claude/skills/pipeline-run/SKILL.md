# Оркестратор конвейера (pipeline-run)

Автономный виток наполнения: берёт «следующее действие» из плана и выполняет его
батчами, держа человека на гейтах. Модель — `vault/product/operating-pipeline.md`.

## Аргументы (опц.)
- пусто → **один батч топ-приоритета** (безопасно, человек в петле).
- `sweep` → пройти несколько групп подряд (до бюджета/гейта); отчитываться после каждой.
- `<action>` (`promote-sorts`|`ingest-sorts`|`brewery-research`|`demand`) → только эта группа.
- `<N>` → ограничить число обрабатываемых сущностей в этом запуске.

## Бюджеты и безопасность (соблюдать строго)
- Параллельных субагентов одновременно — **до 5**; сущностей за запуск по умолчанию — **до 10**.
- **Гейты — НЕ трогать**: `human-review` (спорные сорта) и `blocked` остаются человеку.
- **Скоуп — НЕ решать сам**: новый город/страна/добавление сущности из заявки = человек.
  Если действие упирается в это — стоп, surface человеку.
- Останавливайся, если действие падает 2 раза подряд или очередь пуста.
- Магазин — вторичный источник: канон из него не плодим (политика ingest-shop).

## Цикл

1. **План**: `bun run scripts/pipeline-status.ts --plan` → JSON `{plan:[{action,priority,slugs,how}], gates}`.
   Возьми группу с наименьшим `priority` (или из аргумента). Если план пуст → доложи гейты и стоп.
2. **Диспетчеризация** (по типу действия — см. таблицу). Батчуй независимые сущности в
   параллельные субагенты (Agent tool), каждому в промпте: путь к нужному SKILL.md + slug(и).
   Субагент возвращает результат текстом/файлами (SendMessage недоступен).
3. **Применение**: прогони соответствующий скрипт (детерминированный применитель).
4. **Рефреш**: `bun run scripts/pipeline-status.ts` (дашборд), при изменении каталога —
   `bun run scripts/export-catalog.ts`.
5. **Коммит + лог**: если каталог изменился — `git add -A && git commit` (ветка master,
   подпись Co-Authored-By) + строка в `vault/log.md`.
6. Если `sweep` и есть бюджет/непустой план без гейтов → к шагу 1. Иначе — отчёт и стоп.

## Таблица диспетчеризации

| action | как выполнять |
|---|---|
| `promote-sorts` | группами ~3 пивоварни на субагента; каждый читает `.claude/skills/promote-sorts/SKILL.md`, пишет `data/pipeline/promotions/<slug>.json`. Затем `bun run scripts/promote-sorts.ts data/pipeline/promotions/`. |
| `brewery-research` | по 1 пивоварне на субагента (web-ресёрч), читает `.claude/skills/brewery-research/SKILL.md`, пишет в `links`/`ingest-hints`/`overrides`. Параллельно ≤5. |
| `ingest-sorts` | по источнику пивоварни (из `links`/`ingest-hints`): **Untappd** → добавь в `MAP` в `scripts/ingest-untappd.ts` и запусти; **TG** → `fetch-channels.ts`+`ingest-sorts.ts` (RUNBOOK). Нет читаемого источника → отметь `blocked` в overrides, не выдумывай. |
| `demand` | по городу пивоварни: `.claude/skills/shop-discovery/SKILL.md` → реестр магазинов → скан (`ingest-shop*`). Новый город в скоуп — спроси человека. |

## После прогона — отчёт
Коротко: что сделано (по группам), как изменился дашборд (стадии/сорта), что ушло в
гейты (`human-review`/`blocked`) и ждёт человека, и какой следующий приоритет.

Связано: `vault/product/operating-pipeline.md`, `scripts/pipeline-status.ts`,
`.claude/skills/{promote-sorts,brewery-research,shop-discovery}`, `data/ingest/RUNBOOK.md`.
