# Мета-дайджест каталога (LLM-wiki)

Открытая витрина показывает мету российского крафта на странице `/meta`: числовые
плашки + распределение стилей + **проза-дайджест**. Числа и факты считаются
детерминированно скриптом (без галлюцинаций), а **связный текст пишешь ты** —
это и есть «LLM-проход». Никаких API-вызовов: генерация целиком в рамках агента.

Разделение труда:
- `scripts/gen-digest.ts` — детерминированный сборщик: считает факты, собирает `digest.json`.
- `data/digest-prose.md` — проза, которую пишешь ты по фактам (коммитится в репо).
- Витрина читает `packages/web/src/lib/data/digest.json` (поле `prose` + `facts`).

## Шаги

1. **Свежий снапшот.** Если был ingest/seed — сначала пересобери каталог, иначе факты
   будут от старого среза:
   ```bash
   bun run catalog:export
   ```

2. **Получи факты** (скрипт печатает JSON и ничего не пишет):
   ```bash
   bun run scripts/gen-digest.ts --facts
   ```
   В фактах: `counts` (breweries/beers/cities/beersWithDemand/verified/shopOnly/deals),
   `styleDist` (доли категорий стилей), `topCities`, `topBreweries` и `topBeers` (по
   охвату магазинов = reach).

3. **Напиши прозу** в `data/digest-prose.md` строго по этим фактам. Правила:
   - Markdown: разделы `## Заголовок`, под каждым 1–3 предложения. Жирным `**…**`
     выделяй ключевые числа/названия.
   - 4–6 разделов. Хорошая структура: *Что в каталоге* → *Палитра стилей* →
     *География* → *Где это продаётся* (топ по охвату) → *Насколько данным верить*
     (провенанс: verified / shopOnly).
   - **Не выдумывай** чисел и названий, которых нет в фактах. Каждая цифра в тексте
     должна сходиться с `facts`.
   - Тон сухой, аналитический, по-русски. Подчёркивай: это **рыночные сигналы**
     (наличие, охват, тренды, цены/скидки), **а НЕ потребительский рейтинг** —
     это юр-рамка проекта (vault/strategy/legal-boundary.md, ст. 21).
   - «Популярность/лидеры» = только ширина дистрибуции (reach), не оценки вкуса.
   - Помни про малую выборку магазинов: если потолок reach невелик — оговори, что
     demand-слой на ранней стадии и картина уточняется с каждым новым источником.

4. **Собери дайджест** (подхватит прозу, mode станет `prose-file`):
   ```bash
   bun run scripts/gen-digest.ts
   ```
   Ожидаемо: `mode=prose-file`. Если вдруг `template` — значит файл прозы не нашёлся,
   проверь путь `data/digest-prose.md`.

5. **Проверка.** Пробегись глазами: числа в прозе совпадают с плашками (`facts.counts`),
   названия лидеров — из `topBreweries`/`topBeers`. По желанию — `bun run web:build`
   (он сам прогонит export → digest → build) и глянь `packages/web/build/meta.html`.

## Заметки

- Проза статична и устаревает после ingest — поэтому скилл и нужен: перезапускай его,
  когда числа разъехались. `web:build` пересобирает `digest.json` из текущей прозы, но
  саму прозу обновляешь только ты через этот скилл.
- Гранулярная аналитика спроса (per-seller цены/разбивка) в публичную сборку не идёт
  (гейт `PRIVATE` в `export-catalog.ts`) — в дайджесте оперируй только агрегатами,
  которые есть в `facts`.
